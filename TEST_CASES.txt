NOTES FOR TESTERS

Setup Instructions:
1. Backend Setup:
   - Navigate to backend folder
   - Run: npm install
   - Configure .env file with MongoDB URI and settings
   - Run: node scripts/init-db.js
   - Start server: npm run dev
   - Backend will run on http://localhost:3000

2. Frontend Setup:
   - Install Flutter dependencies: flutter pub get
   - Run on web: flutter run -d chrome
   - Run on desktop: flutter run -d windows (or macos, linux)
   - Run on mobile: flutter run -d <device-id>

3. Database Setup:
   - Ensure MongoDB is running on localhost:27017 or configure MongoDB Atlas URI
   - Use MongoDB Compass to inspect database

4. Test Data:
   - Use backend/scripts/init-db.js to initialize test data
   - Use lib/utils/test_data_generator.dart for generating sample surveys

Test Tools Recommended:
- API Testing: Postman, Thunder Client, curl, Insomnia
- Load Testing: Apache JMeter, k6, Artillery
- Browser Testing: Selenium WebDriver, Playwright, Cypress
- Mobile Testing: Flutter DevTools, Xcode Instruments, Android Studio Profiler
- Database: MongoDB Compass, Studio 3T
- JWT Debugging: jwt.io

Critical Test Paths (Must Test):
1. Complete survey submission flow (TC-E2E-001)
2. Admin login and dashboard access (TC-LOGIN-001, TC-DASHBOARD-001)
3. Data persistence and synchronization (TC-E2E-002)
4. Security measures (TC-SEC-001, TC-SEC-003)
5. API endpoints functionality (TC-API-SURVEY-001, TC-API-ADMIN-001)

Known Limitations:
- Offline sync is manual, not automatic background sync
- Rate limiting is per IP, not per user account
- No email verification for admin registration
- Default admin password should be changed in production
